# Packaging and source debugging

Xdiff uses the Source Link support built into the .NET SDK selected by
`global.json`. No additional Source Link package is required. The portable PDB
maps tracked source files to the exact GitHub commit used for the build. The SDK
also embeds untracked compilation sources, such as generated files, in the PDB.
`PublishRepositoryUrl` includes repository metadata in the NuGet package manifest.

## Build packages

Build from a clean Git checkout whose commit is available on GitHub. In GitHub
Actions, use `fetch-depth: 0` for Nerdbank.GitVersioning and set
`ContinuousIntegrationBuild=true` when building to normalize source paths.
From the repository root, run:

```sh
dotnet restore Xdiff.slnx --locked-mode
dotnet build Xdiff.slnx -c Release --no-restore -p:ContinuousIntegrationBuild=true
dotnet test --solution Xdiff.slnx -c Release --no-build
dotnet pack source/Xdiff/Xdiff.csproj -c Release --no-build -p:ContinuousIntegrationBuild=true -o artifacts/packages
```

The library project produces both `Xdiff.<version>.nupkg` and
`Xdiff.<version>.snupkg`. Nerdbank.GitVersioning determines the version.
The main package contains the assembly, XML API documentation, readme, and license
notices; the symbol package contains the portable PDB. Keep both packages from
the same build together when transferring publishing artifacts.

## Publish symbols

Publish the matching symbol package to NuGet.org along with the main package.
`dotnet nuget push` automatically pushes a matching `.snupkg` beside the `.nupkg`
unless `--no-symbols` is specified. Use the NuGet.org v3 source:

```sh
dotnet nuget push "artifacts/packages/*.nupkg" --api-key "$NUGET_API_KEY" --source https://api.nuget.org/v3/index.json
```

For GitHub Actions, obtain `NUGET_API_KEY` through NuGet Trusted Publishing and
pass it to the push step through an environment variable. A symbol package can
also be pushed explicitly if its upload needs to be retried. NuGet.org validates
and indexes symbols separately; source debugging becomes available after the
matching PDB has been indexed.

## GitHub release workflow

`.github/workflows/publish.yml` runs when a GitHub release is published, including
prereleases. The release commit must contain the workflow and packaging settings.
Tag it as `v<version>`, where `<version>` is the package version generated by
Nerdbank.GitVersioning for that commit. The tag does not override the package
version. The workflow rejects a tag/version mismatch before publishing artifacts.
`version.json` recognizes these tags as public releases.

The build job runs formatting, build, tests, and coverage checks, then packs and
validates the main and symbol packages against the release version and commit.
The publish job downloads that build's artifact by ID on a separate runner and
uses the SDK from the packaged `global.json`. It does not check out or build source.

Configure the GitHub environment `nuget` with your release-tag restrictions and
reviewers, and set its `NUGET_USER` variable to your NuGet username. The NuGet
Trusted Publishing policy must match repository `MM-YJN/Xdiff`, workflow filename
`publish.yml`, and environment `nuget`. Only the publish job has `id-token: write`.
All actions are pinned to commit SHAs.

After committing and pushing the changes, publish a GitHub release for the
matching tag and approve the environment deployment if required. Both packages
are pushed explicitly. If publishing partially succeeds, rerun the failed job:
duplicate versions are skipped so the symbol upload can be retried. A duplicate
response does not verify that an existing package has identical contents; never
reuse a version for changed code or move a published release tag.

## Debug a consuming application

In Visual Studio, open **Tools > Options > Debugging**:

1. Under **General**, enable **Enable Source Link support** and disable
   **Enable Just My Code** when stepping into library code.
2. Under **Symbols**, enable the **NuGet.org Symbol Server**
   (`https://symbols.nuget.org/download/symbols`).
3. While debugging, use the **Modules** window to load symbols for `Xdiff.dll`
   if they were not loaded automatically.

The debugger uses the PDB's Source Link mapping to download the matching source
from GitHub. Release optimization can affect stepping and local-variable
visibility. Source Link requires the referenced commit to remain accessible;
private repositories require debugger authentication. Keep source checksum
validation enabled so a different source revision is not silently used.

See the official [Source Link documentation](https://github.com/dotnet/sourcelink)
and [NuGet symbol package guide](https://learn.microsoft.com/en-us/nuget/create-packages/symbol-packages-snupkg).
